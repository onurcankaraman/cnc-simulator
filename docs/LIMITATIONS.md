# Boundaries and measured acceptance

This is a synthetic CNC process model for demos, connector testing and datasets. Parameters are illustrative, not calibrated machining measurements. It is not a safety system, real PLC controller, G-code interpreter, Siemens device, S7-1200 firmware emulator, or certified OPC UA Machine Tools implementation.

- S7 serves classic DB requests through Snap7. Rack 0 / slots 0 and 1 are externally tested. DB writes are rejected by the resourceless callback. Optimized symbolic DBs, S7CommPlus, TIA programming, MC7 execution and real PLC scanning/control are absent. Snap7 may return legacy generic Siemens-compatible SZL identifiers; those are protocol-library behavior, not a claim of authentic hardware.
- The OPC UA namespace is custom, `ns=2`. Basic256Sha256 + SignAndEncrypt is the default tested path. Certificates are self-signed for localhost; issue certificates with your LAN hostname/IP SAN before remote use. No public Internet exposure is supported. SecurityPolicy None requires explicit opt-in and is only for private testing.
- A synthetic operator performs fault repair/reset after the configured repair duration. `ack-alarm` acknowledges an alarm; it cannot bypass the repair duration. Feed hold resumes its interrupted segment. Severe faults and reboot discard the interrupted cycle without adding a completed part. E-stop is synthetic and automatically reset by the simulated operator after repair; no physical safety claim is made.
- State is durably checkpointed every published snapshot/event and on SIGTERM. A hard process/host crash can lose work since the latest committed checkpoint (normally at most about one second); no completed historical telemetry is invented. PostgreSQL default synchronous commits are retained. Persisted counters/wear/PRNG/order survive normal restart.
- SQL history defaults to 5-second samples. HTTP history selects the first real sample per requested time bucket; it does not average or interpolate. Pagination uses the last returned timestamp plus 1 ms as `from`. Queries filter the strict rolling UTC 24-hour window; cleanup runs every 60 seconds. Runtime state is exempt. No initial backfill is created.
- History responses are chunked and bounded in server memory. Eight HTTP connections and a 3-second request lifetime are enforced; very slow history consumers must use smaller pages. An interrupted stream may be incomplete JSON and should be retried with a smaller page. HTTP concurrency/history queries remain on the small runtime event loop.
- MQTT telemetry is dropped while disconnected. Lost event delivery is counted in `mqtt_dropped`; TimescaleDB remains the event history when writable. During database failure, events are queued up to 256 entries; exceeding that bound fails visibly; health, failure counters, logs and a persisted `sample_gap` on recovery make the gap visible.
- Tool wear increases only while cutting, apart from an explicit tool replacement that resets its lifetime. All 12 slots persist, including spare tools that do not appear in a program. Wear coefficients and rare fault hazards are assumptions, not failure-rate predictions.
- Current-shift OEE includes tool-change time as run time, excludes planned breaks, and counts setup/faults as availability loss. Completed parts contribute ideal cycle time. Ratios are not silently capped to 100%.
- Istanbul uses UTC+03 in the configured calendar. The supplied shift times and break offsets are the supported schedule. Production speed is fixed at 1x; accelerated clocks exist only in C++ tests. The engine continues publishing during planned stops.
- The supplied broker is a separate bundled Compose service. Its image, native protocol sources and native library package revisions are pinned; installed package inventories are recorded in the SBOM. A later rebuild can fail if a pinned Debian package revision leaves the mirror; update pins deliberately and rerun acceptance tests.
- Linux arm64 was built and exercised through Docker Desktop on this host. Linux x86_64 source paths are portable but have not been executed here.
- **24h soak = NOT RUN. 1h RSS = NOT RUN.** Short-run resource measurements cannot establish a 24-hour memory/leak guarantee. See TEST_REPORT.md for actual measurements and remaining acceptance work.
